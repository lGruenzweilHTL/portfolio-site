JavaFX Cheatsheet

Quick-reference notes — property bindings · Stream API · events · FXML · MVC controllers

Properties & basic binding

JavaFX properties (StringProperty, IntegerProperty, BooleanProperty, ...) wrap a value and notify listeners on change. Binding ties one property's value to an expression of others — it updates automatically.

StringProperty firstName = new SimpleStringProperty("Ada");
StringProperty lastName  = new SimpleStringProperty("Lovelace");

// Low-level: bind() ties target to a single source (one-way)
label.textProperty().bind(firstName);

// bindBidirectional: changes flow both ways
textField.textProperty().bindBidirectional(firstName);

// unbind when no longer needed
label.textProperty().unbind();
Bindings class — combining values

The Bindings utility class creates derived bindings from multiple properties without writing a listener by hand.

// Concatenate two properties
StringExpression full =
    Bindings.concat(firstName, " ", lastName);
fullNameLabel.textProperty().bind(full);

// Combine with a custom function
IntegerProperty width  = new SimpleIntegerProperty(10);
IntegerProperty height = new SimpleIntegerProperty(4);

IntegerBinding area = Bindings.createIntegerBinding(
    () -> width.get() * height.get(),
    width, height
);
areaLabel.textProperty().bind(area.asString());
Bindings.format() & conditionals

Bindings.format() mirrors String.format() but stays reactive, re-evaluating whenever an argument property changes.

DoubleProperty price = new SimpleDoubleProperty(19.999);

StringBinding priceText = Bindings.format(
    "Price: $%.2f", price
);
priceLabel.textProperty().bind(priceText);

// Conditional binding ("when")
BooleanProperty inStock = new SimpleBooleanProperty(true);

StringBinding status = Bindings.when(inStock)
    .then("Available")
    .otherwise("Out of stock");
statusLabel.textProperty().bind(status);
Listeners (for non-bindable side effects)

Use a ChangeListener when you need to react with arbitrary code rather than another bound value.

firstName.addListener((obs, oldVal, newVal) -> {
    System.out.println("Changed from " + oldVal + " to " + newVal);
});

// InvalidationListener fires before the new value is computed
area.addListener(obs -> System.out.println("Area is now invalid"));
Creating & transforming streams

List<Person> adults = people.stream()
    .filter(p -> p.getAge() >= 18)
    .sorted(Comparator.comparing(Person::getLastName))
    .collect(Collectors.toList());

Collecting into ObservableList

Streams pair naturally with JavaFX's ObservableList when populating UI controls like TableView or ListView.

ObservableList<String> names =
    people.stream()
          .map(Person::getName)
          .collect(Collectors.toCollection(
              FXCollections::observableArrayList
          ));

listView.setItems(names);
Common collectors & reduce
// joining
String csv = names.stream()
    .collect(Collectors.joining(", ", "[", "]"));

// grouping
Map<Boolean, List<Person>> byAdult =
    people.stream().collect(
        Collectors.partitioningBy(p -> p.getAge() >= 18)
    );

// reduce with identity + accumulator
int totalAge = people.stream()
    .map(Person::getAge)
    .reduce(0, Integer::sum);
EventHandler basics

Most controls expose setOnXxx() convenience methods for the single most common event, backed by the general addEventHandler/addEventFilter mechanism.

button.setOnAction(event -> {
    System.out.println("Button clicked!");
});

// Equivalent, explicit form
button.setOnAction(new EventHandler<ActionEvent>() {
    @Override
    public void handle(ActionEvent event) {
        System.out.println("Clicked");
    }
});
onAction — what fires it
ControlFires onAction when...
ButtonClicked, or Enter while focused
TextFieldEnter pressed
MenuItemSelected from a menu
ChoiceBox / ComboBoxSelected item changes
Timeline / AnimationEach KeyFrame's action fires
onAction vs addEventHandler setOnAction can only hold one handler at a time (overwrites the previous one). addEventHandler(ActionEvent.ACTION, ...) lets you attach multiple handlers to the same node.
Listening to lower-level events
// Mouse events
node.setOnMouseClicked(e -> System.out.println("clicked at " + e.getX() + "," + e.getY()));
node.setOnMouseEntered(e -> node.setStyle("-fx-opacity: 0.8;"));
node.setOnMouseExited(e -> node.setStyle("-fx-opacity: 1.0;"));

// Keyboard events
scene.setOnKeyPressed(e -> {
    if (e.getCode() == KeyCode.ESCAPE) primaryStage.close();
});

// Filters run during the capturing phase, before the target handler
root.addEventFilter(MouseEvent.MOUSE_PRESSED, e -> {
    System.out.println("Filter saw the press first");
});
Minimal FXML layout
<?xml version="1.0" encoding="UTF-8"?>
<?import javafx.scene.control.*?>
<?import javafx.scene.layout.VBox?>

<VBox fx:controller="app.MainController"
      xmlns:fx="http://javafx.com/fxml"
      spacing="10">
    <Label fx:id="titleLabel" text="Hello"/>
    <TextField fx:id="nameField"/>
    <Button text="Greet" onAction="#handleGreet"/>
</VBox>
Key attributes
AttributeMeaning
fx:controllerFully-qualified controller class for the root element
fx:idInjected into a matching @FXML field in the controller
onAction="#method"Binds to a controller method (the # prefix is required)
xmlns:fxRequired namespace declaration for fx: attributes
Common pitfall fx:id must match the controller field name exactly, and the field needs an @FXML annotation — otherwise injection silently fails at load time (NullPointerException later).
Loading FXML & the matching controller
// In the Application's start() method
FXMLLoader loader = new FXMLLoader(getClass().getResource("main.fxml"));
Parent root = loader.load();
primaryStage.setScene(new Scene(root));
primaryStage.show();

// MainController.java
public class MainController {

    @FXML private Label titleLabel;       // matches fx:id="titleLabel"
    @FXML private TextField nameField;   // matches fx:id="nameField"

    @FXML
    public void initialize() {
        // called automatically after fields are injected
        titleLabel.setText("Ready");
    }

    @FXML
    private void handleGreet() {
        titleLabel.setText("Hello, " + nameField.getText());
    }
}
How MVC maps onto JavaFX + FXML
RoleJavaFX equivalent
ModelPlain Java classes / properties holding application state and business rules
ViewThe FXML file (declarative layout) — rendered by the FXMLLoader into a node tree
ControllerThe fx:controller class — wires UI events to model updates
Controller's job Keep it thin: react to FXML-bound events (onAction, etc.), delegate real logic to the model/service layer, and push resulting state back to the view via bindings — don't put business logic directly in the controller.
Controller binding to a model
public class CounterController {

    private final CounterModel model = new CounterModel();

    @FXML private Label countLabel;
    @FXML private Button incrementButton;

    @FXML
    public void initialize() {
        // View binds directly to the model's property
        countLabel.textProperty().bind(
            model.countProperty().asString()
        );
    }

    @FXML
    private void onIncrement() {
        model.increment(); // controller delegates to model
    }
}
Model exposing observable state
public class CounterModel {

    private final IntegerProperty count =
        new SimpleIntegerProperty(0);

    public void increment() {
        count.set(count.get() + 1);
    }

    public IntegerProperty countProperty() {
        return count;
    }
}
Multiple views, one controller class Each FXMLLoader.load() call creates a new controller instance — controllers are not singletons by default. Share state through an injected model/service instead of static fields.
